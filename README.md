# LITTLE HUNTER // PORTAL ANALITIC · локальный визуализированный аналитический портал

Один граф-экран, который работает **без сервера и без установки**: открываете `index.html`
двойным кликом — и видите нодовые блоки, связи, живые ленты и реестр примэрий Молдовы.

## Как открыть

- `index.html` — двойной клик (Chrome или Edge).
- `start-portal.bat` — то же самое, но отдельным окном без адресной строки.

Ничего не ставится, интернет нужен только для «живого» долива новостей и курсов.

## Что на экране

- **Два контура**: `МИР` (планетарный) и `МОЛДОВА` (национальный). Переключение —
  кнопки в шапке, клавиши `Q` / `W`. При переключении меняются наборы карточек,
  счётчики и все связи графа.
- **Шесть тематических нод**: `A` политика · `B` экономика, рынок, коммерция ·
  `C` религии (церкви, синагоги, мечети) · `D` образование ·
  `E` **примэрии Молдовы** (только в контуре МОЛДОВА) · `F` IT и цифровые новшества.
  Клавиши `1`–`6`.
- **Реестр примэрий** (нода `E`): 956 записей реальных местных публичных администраций,
  36 административных единиц. У записей, для которых найден и **проверен** официальный
  сайт, показана ссылка; у остальных — метка «сайта не найдено» (её действительно нет,
  а не «мы не искали»).
- **Курсы BNM** в шапке — читаются из официального XML Banca Națională a Moldovei.

Клавиши: `R` — обновить, `/` — поиск, `Q`/`W` — контур, `1`–`6` — тема.

## Откуда данные и как они обновляются

Данные живут в `data/` и подключаются как обычные `<script>` (так работает с `file://`,
без CORS-проблем). Два пути обновления:

1. **В браузере** — кнопка «обновить». Портал тянет RSS/JSON через CORS-прокси
   (`allorigins`, `corsproxy`, `codetabs`) и курсы BNM, кладёт в `localStorage`
   (ключи `hunter.portal.v1.*`), показывает дату привязки каждой карточки.
2. **Офлайн-обновлятор** (надёжнее, без прокси):
   ```
   powershell -ExecutionPolicy Bypass -File tools\update-cache.ps1
   ```
   Он сам ходит в сеть, пишет `data/parts/news_live_world.json`,
   `data/parts/news_live_md.json`, забирает курсы BNM и в конце вызывает сборку.

Сборка данных из фрагментов: `tools\build-data.ps1` — читает `data/parts\*.json`
и пересобирает `data/primarii.js`, `data/feeds.js`, `data/reference.js`,
`data/sources.js`. После любой правки фрагментов — запускать её.

Поиск сайтов примэрий: `tools\probe-sites.ps1 -Chunk <i> -Chunks 6` — для каждой
единицы реестра перебирает типовые домены (`.md`, `primaria<Nume>.md`,
`primaria-<Nume>.md`, `<Nume>.primarie.md`, `oras<Nume>.md`), проверяет DNS и HTML
и принимает домен **только** если на странице есть официальные маркеры
(`primar`, `consiliu`, `administra`, `primarie`, `uat` …), название самой местности,
нет маркеров парковок доменов и текст страницы достаточно объёмный. Результат —
`data/parts/sites_probe_<i>.json`; дальше его подхватывает сборка.

Ручные подтверждения — `data/parts/sites_manual.json` (там, например,
`primariafloresti.md`, названный человеком, который в этой примэрии работал).
Этот файл имеет приоритет перед автоматическим обходом.

## Честность данных — правило, а не лозунг

- Сайт примэрии попадает в реестр только после проверки адреса и текста страницы;
  в поле `found_in` записано, чем именно подтверждено.
- В справочниках (`data/parts/reference_md.json`, `reference_world.json`) у каждой
  карточки ссылка ведёт на адрес, открытый в день сборки и ответивший `HTTP 200`.
  Там, где адрес проверить не удалось, ссылка не поставлена вовсе, а в тексте
  прямым текстом написано «не проверялось».
- Числа показателей не выдумываются: валютные значения приходят из XML BNM,
  остальное — из лент с датой публикации.

## Карта источников

`data/parts/sources.json` — ключи `world.policy`, `md.market` и т. д., внутри
`{ name, url, kind }`. Добавили рабочий фид — получили новые карточки после сборки.
Фиды, которые на момент проверки не отвечали, в карте помечены и автоматически
пропускаются (портал не падает и не врёт про «0 карточек»).

## Самопроверка

```
powershell -ExecutionPolicy Bypass -File tools\check-portal.ps1
```

Три режима (общий вид, реестр примэрий, планетарный контур) прогоняются в headless
Chrome; считаются ноды, связи, карточки, строки реестра и **ошибки консоли**.
Нормальный итог — `ИТОГО: чисто`.

## Известные особенности среды

- `.ps1` с кириллицей нужно сохранять **с BOM**:
  ```
  powershell -Command "Get-ChildItem tools\*.ps1 | ForEach-Object { $t=Get-Content -Raw -Encoding UTF8 $_.FullName; Set-Content -Path $_.FullName -Value $t -Encoding UTF8 -NoNewline }"
  ```
- В Windows PowerShell 5.1 **нельзя** трогать `[System.Net.ServicePointManager]`
  (ни `SecurityProtocol`, ни `ServerCertificateValidationCallback`) — после этого
  обрывается весь TLS. Флаги `-SkipCertificateCheck` в 5.1 тоже нет.
- Сайт-заглушка `*.primarie.md` (хостинг-шаблон) отсеивается по длине текста.
- Часть сайтов (IMF, OECD, Council of Europe, QS) отдаёт `403` автоматическим
  запросам — в справочники они не включены.

## Что пока не сделано

- Сайты `consiliil raionale` (районные советы) пока могут попадать в запись
  города-райцентра: для них готовится отдельная пометка и замена на адрес примэрии
  (`tools/fix-cra.ps1`).
- Единица реестра `Anenii Noi` (unit_id 1100) не добрана: источник каталога не отдал список (страница id=1100 отдаёт «Hopa, ceva errrori»), ни один домен не подтверждён.
- Сайт примэрии mun. Chișinăу подтвердить не удалось: `pmb.md` в корне отдаёт «Pagina nu a fost găsită», по остальным путям соединение не устанавливается.\n- Точные адреса синагог и мечетей не проверялись — карточки помечены как справка.

## Публикация на GitHub Pages (проверено)

Портал полностью статический: все пути относительные (`app/…`, `data/…`), ни одного
абсолютного адреса. Он одинаково работает и с `file://` (двойной клик по `index.html`),
и по http на GitHub Pages. Проверено локальным http-сервером:
`check-portal.ps1 -Uri http://127.0.0.1:8137/` — тот же результат, что и в файловом
режиме, ошибок JS ноль, живые ленты подтягиваются.

Как выложить:

1. Корнем репозитория должна быть папка этого портала, чтобы `index.html` лежал в корне.
   ```
   cd portal-analitic
   git init -b main
   git add .
   git commit -m "portal: первая публикация"
   ```
2. Создать репозиторий на GitHub и запушить:
   ```
   git remote add origin https://github.com/ЛОГИН/ИМЯ.git
   git push -u origin main
   ```
3. `Settings → Pages → Source: Deploy from a branch → main / (root) → Save`.
   Сайт откроется по адресу `https://ЛОГИН.github.io/ИМЯ/`. Публичный репозиторий —
   бесплатно; приватный требует платного плана Pages.

Что там работает:

- граф, оба контура, реестр примэрий, справочники — из закоммиченных `data/*.js`;
- кнопка «обновить» в браузере тянет ленты и курсы BNM через CORS-прокси прямо со
  страницы Pages (всё по https, смешанного контента нет);
- `.github/workflows/refresh-data.yml` — раз в сутки (02:10, 08:10, 14:10, 20:10 UTC)
  сам запускает `tools/update-cache.ps1` + `tools/build-data.ps1` на GitHub и
  коммитит свежие `data/`. Если сеть или фиды недоступны — шаг обновления не валит
  сборку, и сайт остаётся на последнем снимке данных.

Файлы `.nojekyll` (отключает обработку Jekyll) и `.gitignore` (не тащит в репозиторий
`tools/_logs/` и `data/tmp/`) уже на месте. Регистр имён важен: GitHub раздаёт файлы
с Linux-сервера, где `App.js` и `app.js` — разные файлы; в проекте всё согласовано.

Проверить локальную копию так же, как её увидит Pages:

```
python -m http.server 8137 --bind 127.0.0.1     # в папке портала
powershell -ExecutionPolicy Bypass -File tools\check-portal.ps1 -Uri http://127.0.0.1:8137/
```
